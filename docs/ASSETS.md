# Assets and attribution

Everything rendered in AURORA's orbital station is generated by code in this
repository. No third-party model, texture, photograph, font file, audio file or
other binary asset is bundled, fetched at runtime, or required to build.

This is worth stating plainly, because a 3D environment usually implies an
asset pipeline, and reviewers reasonably ask where the assets came from.

## What that means in practice

| Thing you can see | Where it comes from |
| --- | --- |
| Module shells, rack bays, deck, hatches | `src/features/flight-deck/render/geometry.ts` — built from the deck plan in `model/deck.ts` |
| Suits, galley, medical bay, water rack, seats, cabling, workstations | `render/outfitting.ts` |
| Truss, solar arrays, radiators, antennas, handrails, worksites | `render/exterior.ts` |
| Surface material detail (grain, weave, brushed metal) | `render/shaders.ts` — value noise evaluated per pixel, not sampled from a texture |
| Earth, clouds, terrain, city lights, atmosphere | `render/shaders.ts` — analytic ray–sphere intersection with procedural noise |
| Lighting | Baked per vertex at startup in `geometry.ts`; no lightmap file |

There are no image files in the renderer at all. The only GPU textures created
are render targets the renderer allocates for itself — the shadow map and the
reduced-resolution buffer the planet is composited from.

## Earth

The planet is **procedural noise, not satellite imagery**. It is not NASA Blue
Marble, not a photograph, and not derived from one. It is designed to read as a
plausible ocean, cloud deck and limb at orbital distance, and it will not
survive comparison with a real image of anywhere.

NASA's Earth imagery is in the public domain and would be a genuine
improvement. It is not used here because this build environment cannot fetch
it: outbound network access reaches package registries only. If it is added
later, it belongs in this file with its source and its usage terms.

## Markings and insignia

No agency logo, mission patch, flag, roundel or real flight designation appears
anywhere in the station. Placards, labels and stencil plates are rendered as
blank plates — the shape and placement of a label, without text claiming an
affiliation the project does not have.

The layout is modelled on published imagery of the ISS US segment at the level
of *arrangement*: modules on an axis, a truss carrying arrays outboard and
radiators amidships, handrails along translation paths, racks in standardised
bays. Nothing is traced, measured from, or copied out of a specific drawing,
and no module carries a real name.

AURORA is not affiliated with, endorsed by, or certified by NASA or any space
agency.

## Fonts

The interface uses CSS font stacks resolved by the browser. No font file is
bundled or fetched.

## Medical and crew data

All crew health data is synthetic, generated by `src/lib/` from the mission
model. It describes no real person. Every screen that displays a reading says
so. See `docs/METHODOLOGY.md` for how it is generated and `docs/NASA_DATA.md`
for the published research the indicator set is informed by, with citations.

## If you add an asset later

Add a row here first: what it is, where it came from, its licence, and what the
licence requires. A file that arrives without a row is a licensing problem
waiting to be discovered by someone else.
